# 洞察 01 · 抽取器如何把 34 分凭空变出来

> 同一批 100 道 GSM8K、同一个模型（DeepSeek）的生成结果，只换一个「答案抽取器」，分数就从 64% 跳到 98%。
> 模型没变，题目没变，生成的文本一字没改。

## 现象

| 答案抽取器 | exact_match | 样本 |
|---|---:|---:|
| `strict-match` | **64.0%** | 100 |
| `flexible-extract` | **98.0%** | 100 |
| **差值** | **34.0 个百分点** | |

复现：`python3 replay.py`

## 真正的机制（不是"抽取器偏好"，是格式协议）

`strict-match` 几乎只认 GSM8K 原生锚定格式——模型必须在推理末尾写出 `#### 数字`。
DeepSeek 没有按这个格式收尾。它习惯用 LaTeX `\boxed{}` 给最终答案。
于是 strict 把所有非 `####` 结尾的输出一律抽成 `[invalid]`，直接判 0 分。

证据来自固化数据的逐题对照：

- **strict 判对的 64 道，100% 以 `#### 数字` 结尾。**
- **strict 判错 / flexible 判对的 34 道，全部没有 `####`**——其中 **28 道用 `\boxed{}`**，其余 6 道用了其他收尾方式。
- `flexible-extract` 不认锚定，它用正则从整段输出里抓最后一个数字，于是把 `\boxed{20}` 里的 `20` 捞了回来。

**34 分差 = 34 道格式不符的题，一道 1 分，严丝合缝。** 不是统计噪声，是确定性的格式协议错配。

## 一道具体例子（题 #4）

> Wendi 每天给每只鸡喂 3 杯饲料，共 20 只鸡……早 15 杯、午 25 杯，最后一餐还要多少杯？

DeepSeek 的推理和答案完全正确：

```
… Total given so far: 15 + 25 = 40 cups.
  Cups needed for the final meal: 60 − 40 = 20 cups.
  \boxed{20}
```

金标答案就是 `20`。但：

| 抽取器 | 抽出 | 判 |
|---|---|---|
| `strict-match` | `[invalid]` | ✗ |
| `flexible-extract` | `20` | ✓ |

模型算对了，只是没用 `####` 这个 GSM8K 老格式收尾，strict 就判它错。
（看更多：`python3 replay.py --examples`，会列出全部 34 道。）

## 这说明什么

> **strict-match 把「输出格式不符合 GSM8K 锚定」误读成了「模型数学能力不足」。**

这是把**协议 / 格式问题**误写成**能力问题**的典型案例。`98%` 不是在吹牛，`64%` 也不是在唱衰——它们测的根本不是同一件事：

- 想测「模型能否遵循 GSM8K 原始答题协议」→ 用 `strict-match`，64% 是协议遵循分。
- 想测「模型会不会做这道数学题」→ 用 `flexible-extract`，98% 是数学能力分。

两个数字都对，前提是你写报告时**配套写清楚用的是哪个抽取器**。只写一行「GSM8K 98%」或「GSM8K 64%」，读者都会得到错误结论。

## 对交付的启示（FDE 视角）

1. **跑评测前，先搞清楚你的 scorer 认什么格式。** 这是工程动作，不是学术偏好。scorer 与模型输出协议错配，会把好好的模型评成废铁。
2. **模型用 `\boxed{}` 收尾是「会做数学」的强信号，不是「不会」。** 在生产里，与其换 scorer，不如在 prompt 里要求模型用固定格式输出（few-shot 示例用 `####`），从源头对齐协议。
3. **评测分数必须按「模型 × 任务 × 抽取器 × 样本量 × seed」披露，缺一项都可能误导。** 本仓库的固化数据把这几项都记在了 `data/gsm8k_deepseek_results_meta.json`。
4. **标准 benchmark 负责横向比较（和别家模型对齐口径），不负责回答「我的业务场景能不能用」。** 后者是[洞察 02](02-public-vs-private-bench.md) 的事。

## 边界

- 这 100 道题是 GSM8K 测试集在 `seed=1234, limit=100` 下的取样，不是全量 1319 题。样本足够展示机制，**不构成模型排名**。
- 34 分差的机制（strict 只认 `####`）在 lm-eval 0.4.12 + `local-chat-completions` 后端下成立；换任务、换模型、换抽取器版本，数字会变，但「分数 = 模型能力 × 评测方法」这层关系不变。
- 原始逐题 responses 已固化在 `data/gsm8k_deepseek_samples.jsonl`，可独立复核，不含任何 API 凭据。
